# SysTorch M0：工作面、状态与继承合同

> 2026-10-24 · M0 交互原型合同。入口为 Vite 的 `/systorch-preview.html`，不是生产 App 路由；默认生产构建不打包该 HTML。当前展示文字以中文探索，生产国际化尚未接入。

## 工作面与现有功能

| 工作面 | 第一件可以做的事 | 已有能力怎样保留 |
|---|---|---|
| 开始 | 选择明确入口，填问题/候选或套用模板，请求判断 | 将来复用现有公开入口和 readiness；不靠额外 LLM 解析任意输入，不静默换源 |
| 决策台 | 找到需要自己回答的请求，理解上下文，选择后显式提交 | 与调用历史/实验样本按请求关联；不把已选中当作已提交 |
| 协调工作台 | 管理来源、查看/编辑 DAG、进入比较或追踪 | 提供商、入口、DAG、统计、演练场和设置保留专业操作，不被新首页替换 |

导航首选级草案：已授权任务深链 → 用户明确导航 → 配置的默认首页。原型支持“开始／仪表盘／最近访问”偏好，其中仪表盘仅在该隔离演示中映射到协调总览；真实 Dashboard 仍保持原页面和组件布局。

手机使用相同的对象与动作，改为顶部工作面导航；请求清单按需展开，避免先浏览全部待办才找到当前问题。长内容允许纵向阅读，去除可见滚动条；图内使用平移/缩放，不把画布换成横纵滚动容器。

## 不可丢失的辨识度与验收基线

维护者在 M0 预览中再次明确：DAG、提供商启停、DAG 请求辉光等核心特性不能丢。

| 保留项 | 本轮处理 | 证据边界 |
|---|---|---|
| 可编辑 DAG、模型端口、多跳、跨层走廊、选中、重连、平移、缩放 | 生产组件与几何保持；协调原型直接复用 `DagCanvas`，编辑只进入模拟会话 | 现有 DAG 单元回归；浏览器原型布局检查。没有声称新的手机真机手势验收 |
| 请求曝光、在途亮度、响应辉光、健康色混合、自然淡出 | 复用实际 `routingActivity` 与 SVG 渲染器；原型按钮产生明确标为模拟的事件 | 浏览器验证多请求、响应淡出、切页返回不重播；真实事件源仍为原 daemon |
| 提供商启停、readiness、启动/停止/状态反馈、进程策略 | 原 UI/API/生命周期状态机保留；配置写入加入共同发布门，状态探测前释放门 | Rust 生命周期与配置回归；没有实际启动/停止 Laya 等服务 |
| 入口/提供商双视角历史、attempt、统计、演练场和布局 | 保留生产入口和数据口径；原型只增加新工作面，不迁移旧数据 | 现有回归与源码差异检查；没有把演示请求写入生产历史 |

协调原型已提供七项现有专业功能的导航链接，另开原 Jev Switch 控制台并使用其已有网关配置；打开链接前不会自动连接。完整专业操作必须始终可达。小路径示意不能取代完整 DAG，提供商服务状态不能被一个通用健康徽标取代，人工等待也不能伪造为模型 HTTP attempt。

## 原型状态合同

| 情境 | 用户能看到/做什么 | 禁止的含混 |
|---|---|---|
| 无入口 | 配置模拟入口，或明确使用模拟样例 | 不伪造已配置模型/凭据 |
| 加载 | 明确读取反馈，暂不展示可编辑的未确认配置 | 不把空表当作真实无配置 |
| 正常 | 选择明确来源，填写、提交、查看模拟结果及来源注解 | 不把固定样例当模型推理 |
| 忙碌 | 操作立即出现反馈，防重复，可取消本次模拟操作 | 动画不冒充精确进度；旧回调不可恢复已取消操作 |
| 断网/提交失败 | 保留问题、选项、人工选择和条件草稿，提供重试 | 未接受时不显示完成 |
| 本地来源未启动 | 明确提示来源未就绪，提供模拟启动；ready 后才可发送 | 不暗中切付费远端；命令启动不等于 ready |
| 过期 | 旧答案不可提交，有重新发起的指引 | 不复活旧授权 |
| 其他设备已回答 | 保留旧草稿，查看最新结果 | 不覆盖胜出的回答 |
| 无权限 | 展示范围说明，禁用作答 | 任务 ID 不是作答许可 |
| 拒答 | 明确未提供业务答案 | 不编码成随机选择或批准 |
| 附条件 | 条件与回答一起可读，并提示 strict 投影边界 | 不丢掉条件冒充无条件同意 |
| 补充信息 | 原型可快进到新修订并清除旧选择，演示迟到回答边界 | M1 中需由调用方补充权威上下文，作答方不能自行改事实 |
| 返回/刷新 | 选择、问题、条件和补充草稿保留；最近访问偏好生效 | 恢复不重新播放一次性响应 |

焦点、预览和选择均不提交。普通 Enter 在多行文本中换行；Ctrl/Cmd+Enter 仅在当前提交范围生效；输入法组合、按住重复键不触发提交。拒答和请求补充有独立操作。

## 模拟与实际的边界

- `model.ts` 的 reducer 是模拟状态，不是 daemon 持久任务引擎。
- 存储使用独立 `systorch-m0-preview-v1` 浏览器键；不读取真实 provider/key，不连接 `/v1`。复用 DAG 只读取其现有 HUD 显示偏好，不改生产偏好。
- DAG 编辑历史和事件归属由预览父会话持有，跨工作面保留；完整刷新会重建模拟图。判断表单草稿则保存在该浏览器的独立演示存储中。
- 请求/成功/失败按钮手动产生模拟事件，不循环制造“实时流量”。页面隐藏或切换会清理绘图计时器，回到图中按原事件时间继续衰减。
- 原型只呈现“模拟已接受”，没有真实调用方取回、确认、业务执行或校准概率。
- 本原型只展开单题 Choice；默认模板、Noul/Score、多问题/媒体、真实权限和跨设备同步需在相应实现阶段接入，不能从原型推断已经支持。

## M1 首个垂直切片 API 草案

以下路径均**尚未实现**，不是可调用接口或 TypeSafe 官方 API。首个实现先覆盖无害的人工 Choice，继续保留即时 `/v1/systemone` 合同。

| 操作草案 | 权限/语义 | 返回草案 |
|---|---|---|
| `POST /v1/systorch/decisions` | 已识别调用者；请求使用现有 `model/state/questions`，入口决定来源；幂等键绑定调用者、入口及内容 | 落盘后才 `202`，返回请求 ID、修订、截止时间与相对 Location |
| `GET /v1/systorch/decisions` | 按调用归属或明确作答范围列出；分页/状态筛选 | 不暴露其他人的上下文 |
| `GET /v1/systorch/decisions/{id}` | 请求所有者、指定作答者或获权管理者 | 权威状态、修订与许可范围内的内容 |
| `POST /v1/systorch/decisions/{id}/answers` | 明确作答权限；提交修订与真实观察；幂等重复提交只有一个有效回答 | 已接受的同一结果，或可读冲突/过期/无权限错误 |
| `GET /v1/systorch/decisions/{id}/result` | 调用方取回；strict 与增强视图显式区分 | 可表达时 strict `200`；待答仍是收据；拒答/条件不可表达时明确结果错误 |
| `POST /v1/systorch/decisions/{id}/cancel` | 调用方/获权管理者的意图操作，不是关窗回调 | 条件取消；不重写已完成结果 |
| 澄清/上下文修订 | 提问与调用方补充分别授权；旧回答绑定旧修订 | 路径与具体字段在 M1 实现前冻结，不用任意整对象 PUT |

尚需 M1 冻结的细节：作答凭据如何在本机建立、标准问题批次的完成规则、各非答案结果的精确状态码/strict 客户端行为、正文的加密/密钥恢复/留存。原型不替这些安全和兼容决定提供通过证据；已有 local loopback 免鉴权也不能直接充当作答身份。

UI、脚本和 Agent 使用相同操作合同。结果取回不等于调用方确认，更不等于外部动作已经执行。首轮使用查询/轮询恢复，不提前增加 webhook 或复杂租约服务。

## 预览与复核

启动：在 `ui/` 下运行 `node node_modules/vite/bin/vite.js --host 127.0.0.1 --port 5173 --strictPort`，打开 `/systorch-preview.html`。右上角“预览设置与情境”可切换全部状态、默认首页与演示重置。“深色模式”使用固定名称、aria-pressed 与激活色区分状态，独立于生产偏好。

自动检查：`scripts/verify-systorch-preview.mjs` 使用独立 Chromium 测试桌面、窄桌面与触摸视口、状态矩阵、IME/取消/草稿/权限/辉光；`scripts/verify-route-editor.mjs` 则用 mock HTTP 验证生产路由编辑器。脚本需要可解析的 Playwright 包（可通过本机工具运行时的 `NODE_PATH` 提供），不修改项目依赖。结果与局限见[本轮验证](../verification/systorch-m0-2026-10-24.md)。
