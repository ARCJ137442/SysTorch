# SysTorch M1 新版验收

> **历史候选说明**：本指南对应 2026-10-29 的 0.10.3 M1 本地预览，不是 SysTorch 0.12.0 Release 安装说明；新版 Release 的安装与验收边界见 [0.12.0 发布说明](../releases/0.12.0.md)。

本指南当前对应本地测试候选 `m1-systorch-20261029.1`，基础版本仍为 `0.10.3`。2026-10-24 的 `.5` 是冻结基线。本候选不是正式发行；文件、哈希、自动验证与未覆盖边界见[本轮核验记录](../verification/systorch-start-ui-multichoice-2026-10-29.md)。先验 Windows，再验 Android，便于区分通用功能与平台问题。

## 1. 更新前与身份确认

Windows 运行 `SysTorch-m1-preview-20261029.1-windows-x64.exe`。这是独立 M1 测试身份，数据不会覆盖正式版或旧 M1 数据。关闭窗口仍可能只是隐藏到托盘。Windows Authenticode 尚未签署，因此系统仍可能提示未知发布者。

Android 首次安装 `SysTorch-m1-preview-20261029.1-aarch64.apk`，它使用独立 `.m1preview` applicationId，可与正式版并存。之后同一候选系列更新用覆盖安装。沿用 M1 专属测试签名；它不是正式稳定 APK 的签名。此 APK 还没有在 AVD 或真机上完成交互验收。

打开设置里的构建信息，或查询本机测试网关：

```powershell
Invoke-RestMethod http://127.0.0.1:11436/health |
    Select-Object product, version, build_revision
```

应见 `version=0.10.3`、`build_revision=m1-systorch-20261029.1`。`product=jev-switch` 是兼容协议字段，保留它不代表打开了旧 UI。手机上的 `127.0.0.1` 指手机自身，电脑无法靠这个地址自动访问手机。

Windows EXE 未做 Authenticode，系统仍可能提示未知发布者；本轮不以图标或名称变化宣称解决签名问题。

## 2. 先验证“升级没有丢东西”

- 检查旧 M1 中已有的提供商、路由、启停命令、语言、主题和缩放设置；不要为了测试重填一遍配置掩盖丢失。
- 决策台应保留旧待答任务、已答结果和取消／过期状态。选择一条旧待答任务，在新版中作答；原调用方使用**原 Token、原任务 ID**仍应取回结果。
- 完整退出再打开，确认本次回答仍在；重复提交原幂等键不新增第二条任务。
- 正式版与 M1 没有共享任务队列。设置 JSON 备份也不包含完整任务数据库和配套加密密钥，不应拿它替代任务迁移或完整数据备份。

## 3. 走一次真正的产品闭环

按[外部 Choice 示例](SYSTORCH-EXTERNAL-CHOICE.md)，进入 **统计 → 访问与活动 → 调用 Token → 创建 Token**，创建外部程序的调用身份。它**不是提供商 API key，也不是决策台的本机回答权限**。

1. 外部程序提交 Choice，收到任务 ID 后退出。
2. 在 APP 决策台打开题目，选择选项。尚未点击提交时只是一份草稿，调用方应仍看到等待。
3. 明确提交回答，看到保存反馈。
4. 重新运行独立查询程序，以原 Token／任务 ID 取回同一结果。
5. 另建一条任务保留等待，重启 APP 后再回答。再试一条拒绝或条件回答，确认它不会被伪装成无条件批准。

再从「开始」界面测试多题 Choice：选择「交给我回答」，填写问题 A 和候选，点击 `+` 将问题加入队列；填写问题 B 后点击发送。决策台应显示同一个任务里的两题；一次选择两个答案并提交后，两题应同时保存，调用方从同一个 `/result` 响应中按 `question_order` 对应的 ID 取回两个答案。只提交一道题的 API 客户端应看到任务仍为 `pending`；同题重复答案幂等，改成另一个答案则冲突。此候选只有 Choice 多题人工决策，不支持附件、Noul、Score、Box。

本轮真实闭环只覆盖个人 Choice。人工答案投影中的 one-hot 数值是编码方式，**不是人的置信度校准**。作答不会自动执行选项所描述的现实行动。

## 4. 再验证旧产品的辨识度

- 路由图继续是无限画布：平移、缩放、选中、DAG 长边和点击区域可用，不出现横纵滚动条。
- 有真实请求才出现整条连线曝光，有真实响应才出现一次辉光，离开再返回页面不应重播历史响应。为本次验收选本地或合成服务即可，无需反复发付费调用。
- 提供商的服务启停入口、展开状态和 readiness 反馈仍在。不要为测试停止其他工作使用中的模型；可以复用自己空闲时已配置的服务。
- Android 在“开始”和“路由”页试通知或 Quick Settings tile 的启停；不应先进入仪表盘才能工作。明确停止后重开 APP 应继续保持停止，手动启动应能通过原生 RPC 拉起网关。该项在本轮 APK 上尚未由自动化或真机验证。

## 5. 看图形与界面，而不只看名字

应用、窗口、任务栏、Android 启动入口和最近任务应是**同一 SVG 火炬派生的彩色图形**：暖色亮芯、冷色结构、深色背景。托盘、通知小图标和启用 Android 主题图标时允许单色适配，但轮廓应一致，不能回到字母 S、旧 J 或 Tauri 模板。

分别看浅／深系统背景、小图标和放大显示：能否认出同一个产品，火把还是更像别的物体，亮芯是否清楚但不刺眼。图形是候选设计；自动像素门禁证明资源一致，不能代替你的识别与审美判断。

最后在手机竖屏和桌面窄窗口检查题面、选项、提交按钮、错误提示及构建身份是否完整可见。等待、未连接、已保存不能只靠一种颜色区分。

## 反馈方式

反馈包含“平台／构建 ID／所在页面／操作步骤／预期／实际”，出错时附请求 ID 或脱敏截图。不要贴完整 Token、API key、owner 密钥、真实敏感题面或私有数据目录。若升级未通过，先保留现状和原安装包，不通过卸载、清空数据库或重建密钥来试错。
