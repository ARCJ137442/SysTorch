## 2. 这次方向改变在哪里

SysTorch 的核心对象将从“一次模型调用”扩展到“一项可以发起、转交、回答、追踪并取得结果的判断请求”。调用者、协调者、判断来源是三个职责；人、模型和程序可以分别参与，不要求使用者先成为网关管理员。

这带来三条同样合法的使用路径：

1. **直接使用判断**：从“开始”选择当前入口，填写问题和候选，取得清晰的决策结果。技术细节按需展开。
2. **提供判断**：从“决策台”接收外部请求，理解上下文、作答或说明无法回答，让调用方取得有归属的结果。
3. **协调判断**：继续使用提供商、入口、DAG、服务启停、历史与统计，安排来源和故障处理；专业人员进入实验场比较不同来源。

“开始”不是泛用长文聊天；“人类 Provider”也不只是把现有模型卡片换成人名。后者增加了等待、修订、权限、重复提交、过期和恢复责任。保留原有工程能力，才能把简单入口与专业排查连起来。

## 3. 吸收“人类决策后端”分析，但修正落地方式

| 分析中的洞见 | 保留与落地 | 需要纠偏的地方 |
|---|---|---|
| 人可以与模型使用相似问题形状 | 保留类型化问题与结果投影，新增人工作答流程 | 同形状不等于同置信度、同授权或同响应时延 |
| 人工作答应脱离单条 HTTP 连接 | 持久接收、查询状态、查询结果；调用方决定何时继续 | 异步不保证依赖该回答的分支可以继续；协调方不接管任意 Agent 的全部调度 |
| 队列、旁路提示、提问和恢复是不同能力 | 作为集成合同逐项说明 | 不能承诺自动截获 Codex 或其他软件的所有问题 |
| 多 Agent 向一个人请示 | 请求归属、上下文修订、幂等和容量必须先成立 | 相似文案不代表同一对象或同一权限，不能任意合并请求 |
| 用户偏好可帮助后续判断 | 将来可提出可审核规则候选 | 历史不自动变成训练数据或永久规则；拒答不能反复重试到同意 |
| 决策 Broker 包含收件箱、结果交付与审计 | 由现有 Rust daemon 增量承载 | 不照搬绿地 FastAPI/Node 重建；不把 pending、read、delivered 混成一个状态枚举 |
| 团队/公众参与有潜力 | 后续独立实验方向 | 多数投票不产生业务权限；群体结果不等于可执行批准 |

首个示例宜是无破坏性的 Choice：一个脚本提交“下一项先整理 A 还是 B”，人在决策台选择，脚本通过请求 ID 取回答案。它先证明关联、恢复和兼容，不把“已回答”展示为“外部动作已完成”。

## 5. 需要先调整的具体问题

### A. 原子 API 与原子用户意图还没有完全对齐

[UI `putRoutes`](../../ui/src/api/admin.ts) 约 676–708 行接收完整草稿；再 GET 当前边表，对当前有而草稿没有的边生成 delete。若 A 打开旧草稿，B 添加边，A 保存自己的一项改动，B 的新增边也可能被删除。这是静态可构造风险，本轮未对真实网关执行复现。

建议 UI 从编辑时的基线记录 create/update/delete 意图，只发送明确改过的边；未触及边不生成操作。对同一条边被别人改过的情况，优先考虑操作附带原值前提并返回可读冲突，不预先强加全局 ETag 服务。此类必要前提与“如无必要勿增实体”的要求并不冲突。

### B. 数据库原子提交不等于所有运行投影同时发布

`route_transaction` 在保存快照后释放数据库锁，再 `registry.replace_edges`（约 1399–1408 行）。provider、入口也各有投影刷新路径。并发写入可能出现提交顺序与内存发布时间不同，需要以隔离并发用例确认影响；目前不能宣称已实际触发配置损坏。

修正方向是统一必要的写入/发布临界区和失败恢复，避免跨 await 持锁；范围只覆盖受影响路径，不借机引入通用分布式配置系统。

### C. 真实请求内容落盘是新的隐私责任

当前调用 trace 明确不存请求/响应正文。人工任务要恢复上下文就必须增加内容存储、访问控制、留存、删除和备份边界；不能照抄调用日志保留策略，更不能默认把完整任务内容打进日志、通知或支持包。加密需求与密钥恢复方案必须在持久载荷开放使用前核定，不写空泛“端到端加密”承诺。

### D. 原型、兼容和发布的“通过”必须分开

设计包的数学 fixture、报告阅读器检查、现有 v0.10.x 人工验收，都不能证明新的持久人机闭环已完成。新的严格结果投影需针对确切 wire/SDK 版本验证；已有即时响应含 route trace 等扩展，也不能简单宣称它就是包内提出的严格结果视图。

## 6. 不可混淆的语义

- 人的“选中 A”是观察事实；one-hot/平滑概率是带策略版本的派生值；它们都不是独立校准后的正确率。
- 拒答与取消、业务选项中的“拒绝”、附条件同意是不同结果；不能静默互换。
- 连接等待、任务截止、结果留存分别计时。HTTP 断开不自动取消任务，留存到期不提前删除仍在等待的请求。
- 已选中、已提交、服务器已接受、调用方已取回、调用方已确认、业务已执行分别反馈。没有显式确认机制时不能显示“已确认送达”。
- 服务协调可以保证本系统中的幂等提交和单一胜出答案，不能保证外部业务动作 exactly once。
- 即时模型任务中断后，上游是否已计费可能未知；不能在重启后自动重放。人工作答仍 pending 的请求可以恢复等待。
- Box 不存在不能用零框冒充；图像传递扩展不等于 Box 协议、坐标和 UI 已支持。
- 汇总一致率不是准确率；辅助作答与独立盲答、人工权重与模型原生概率分别统计。

## 7. 竞品、学习与品牌材料怎样继续使用

包内 W21 和 C01–C28 已纠正一批实体/证据混用。正确 ExoMind 锚定 `exomind-team/exomind`；关于 ExoMind 的亲友反馈与使用者自身的 TouchAI 内存摩擦分别保留，不能拼成一个对照实验。Bud、Jev 客户端/模拟器/演练场和 Magpie 仍是需要正面比较的对象，不以“对方不会做”推导壁垒。

后续每个阶段用同一个真实任务比较 SysTorch、强对手与“脚本 + 表单/IM”的替代方式：谁能更少配置、少打断、可恢复且代价可接受。开源功能可以借鉴，但复制代码前另查当前许可证；本轮没有重新联网核实维护速度、社区数据或授权条件。

制作人学习不是额外功能清单：品牌回答承诺什么，原型检验用户能否理解，真实任务检验是否值得采用，资源实测检验是否愿意长期保留，发行和支持检验能否持续维护。Astra 的学习复盘与 Luna 的实现记录共用 R/D/W/AC ID，但不由一个讨论模型的建议自动改变实现范围。
