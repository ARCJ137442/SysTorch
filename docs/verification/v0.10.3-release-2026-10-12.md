# v0.10.3 代理修复发布核验

日期：2026-10-12。版本：`0.10.3`，正式 fix，无预发布后缀。

## 交付与验证状态

本版包含 Windows 系统代理读取、上游/探测/readiness 的回环直连边界，以及 451 非重试回归。版本字段与 npm/Cargo 锁文件保持一致，正式资产由 `v0.10.3` tag 的 Release workflow 构建。

用户已授权直接发布补丁，发行包真实推理与原生 UI 留到发布后验证。源码回归与诊断结果不替代发行包验收，也不将 v0.10.1 的本地服务人工结果计为本版已验收。Release 的构建、资产及 Pages 状态以 Actions 结果为准。

## 用户叙事与对照场景

- **起点**：Windows 用户开启系统代理，在 Jev Switch 登记官方 TypeSafe endpoint、API key 与 `jev-latest`。
- **问题**：浏览器出口正常，daemon 却直连；官方返回 451 地区不可用。由于未启用 reqwest `system-proxy`，系统设置没有进入 Rust HTTP 客户端。
- **操作**：完整退出旧 APP/托盘，启动本版；在提供商页刷新模型目录确认网络与鉴权，再到演练场进行一次实际 Jev 调用。
- **结果**：诊断对照中，系统代理路径的 Rust 客户端取得官方模型目录 HTTP 200 和 2 个模型；旧客户端直连仍为 451。当前没有实际推理结果可报告。
- **对照**：云端上游遵循代理；Laya、StartLux、OneJev 等本机回环服务始终直连。代理生成的 502 不再使未启动本地服务被误判为可达。
- **边界**：本版不提供代理节点、不绕过 TLS 校验，不改变 TypeSafe JSON 格式；地区识别与上游政策由网络/供应商决定。Linux/Android 没有新增系统代理读取行为。

## 发布前证据

- 网络对照与官方目录鉴权：[TypeSafe 系统代理核验](typesafe-system-proxy-2026-10-12.md)。仅目录请求，无付费推理。
- Windows 本地默认/ts-rs Rust workspace 回归通过；adapter 新增回环边界与 451 非重试测试。
- daemon 未启动端口 probe、路由/历史集成、11 项监听重绑定回归通过。
- fmt、Clippy `-D warnings` 与 Tauri locked 编译检查通过；ts-rs 属性解析仍有既有非阻断提示。
- UI 未改业务行为；发布门禁继续检查 npm 测试、lint、build、Rust 锁文件与生成类型。
- GitHub About 已核对为英文一句话与中文一句话的双语格式，定位仍为 Jev 模型网关。

## 发布后验收（尚未完成）

1. 下载本版 Standalone/Portable，核对 `/health` 的 `0.10.3` 和 tag 对应 build revision。
2. 保持系统代理开启，以原官方 provider 凭据刷新模型目录。
3. 在演练场发送一次官方 TypeSafe Jev 请求；记录 HTTP 状态和 request ID，不记录凭据或私有正文。
4. 关闭本机测试模型后确认 probe 显示不可达，再抽查一次正常 readiness；不停止其他项目进程。

Windows Authenticode 仍遵守仓库既有签名开关，未签名资产必须如实标注；Android APK 继续使用 Jev Switch 专属稳定签名。资产可下载与上述运行验收分别记录。
