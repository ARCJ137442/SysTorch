## API 与兼容核验

- canonical 即时请求为 `POST /v1/systorch/systemone`。它保留 `model/state/questions` 核心，可附 `question_order`；服务端验证该顺序是全部问题 ID 的精确排列，并在 adapter 边界消费它。
- TypeSafe adapter 只收到兼容核心。旧 `POST /v1/systemone` 继续接受既有 wire shape，普通错误体保持三字段。
- canonical 请求失败时可返回安全 per-provider `route_trace`。会话失败消息只保存现有错误摘要和 request ID，不扩张严格的加密会话消息 union；开始页展开失败轨迹时，从已有 `/v1/events/my` 或 `/v1/admin/events` 按权限和 request ID 查询。
- `/v1` 请求统一 `Cache-Control: no-store`；成功与失败都暴露 `x-systorch-request-id`，并保留 `x-jev-request-id` 兼容头。
